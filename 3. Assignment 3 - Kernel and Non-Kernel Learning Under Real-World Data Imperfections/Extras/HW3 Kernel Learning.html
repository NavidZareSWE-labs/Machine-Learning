Problem Overview

Understanding the assignment's core challenge before touching any code

The Core Question

This assignment asks a deceptively simple question: When does the dataset matter more than the algorithm?

Traditional ML courses present clean datasets (Iris, MNIST) where algorithm selection dominates performance. Real-world data is inherently flawed — missing values, outliers, class imbalance, and complex nonlinear manifold structures challenge every assumption. This project investigates how these imperfections interact with algorithm choice across four fundamentally different datasets.

Grading Emphasis

The grading split reveals the assignment's philosophy: understanding data is more important than implementing algorithms. This mirrors production ML, where data scientists spend ~80% of their time on data preparation.

What Makes This Different From Textbook ML?

1. Missing data is the norm, not the exception▼

The Airbnb dataset has 24 features with missing values. Textbook datasets like Iris have zero missing values, creating a false impression that missing data is a minor preprocessing step.

2. Class imbalance changes the entire problem▼

IBM HR has a 5.20:1 imbalance ratio (83.9% non-attrition vs 16.1% attrition). A naive model predicting "no attrition" for everyone achieves 83.9% accuracy while being completely useless. SMOTE was needed to produce meaningful classifiers.

3. Feature engineering dominates algorithm selection▼

The Online Retail dataset requires complete transformation from transaction logs to customer-level RFM features before ANY model can be applied. The raw data structure is fundamentally incompatible with standard ML inputs.

4. The kernel trick is not universally beneficial▼

While kernel methods provided uplift on Airbnb (+3.45%), they underperformed Decision Trees on three of four datasets. Textbook demos on toy 2D datasets (concentric circles, XOR) create a misleading impression of kernel superiority.

Conceptual Foundations

Understanding the theory before seeing the code

The Kernel Trick (Lecture 7)

The Problem

Given data that is not linearly separable in the original space, we want to find a nonlinear decision boundary. One approach: map data into a higher-dimensional space where a linear boundary exists.

The Insight

Explicitly mapping data to high dimensions is expensive. But many algorithms only need the dot product between mapped vectors, not the mapped vectors themselves. A kernel function computes this dot product directly:

Kernel Function Definition (Lecture 7, Slide 6)k(x, z) = φ(x)T · φ(z)

This is the kernel trick: replace every inner product with a kernel evaluation, avoiding explicit feature mapping entirely.

Three Kernel Types (Lecture 7, Slide 9)

Linear
k(x, x') = xT x' + c

Simplest kernel. Equivalent to standard linear methods. Use when data is already (approximately) linearly separable.

Polynomial
k(x, x') = (α xT x' + c)d

Captures polynomial interactions up to degree d. With d=3, models up to 3-way feature interactions.

RBF (Gaussian)
k(x, x') = exp( -‖x - x'‖22σ2 )

Maps to infinite-dimensional space. Similarity decreases with distance. Most flexible but sensitive to σ.

Kernel Ridge Regression (Lecture 7, Slides 13–16)

From Primal to Dual

Step 1: Primal Form (Slide 10)

Ridge Regression - Primal Form (Slide 10)w = ( XT X + λ I )−1 XT y

This solves for the weight vector w directly. Complexity depends on the number of features (d).

Step 2: Dual Form (Slide 13)

Dual Form (Slide 13)α = ( X XT + λ I )−1 y

Key insight (Slide 12): w = Xᵀα, meaning w lies in the span of training examples. Complexity depends on the number of samples (n).

Step 3: Kernel Trick (Slide 16)

Kernel Ridge Regression (Slide 16)α = ( K + λ I )−1 y   where   Kij = k(xi, xj)
Prediction Functiong(x) = Σi αi · k(x, xi)

Replace XXᵀ with the kernel matrix K. Both steps only involve inner products — so we can use ANY valid kernel.

Outlier Detection Methods

Z-Score
z = x - μσ,   outlier if |z| > 3

Assumes approximately normal distribution. Fails on skewed data. Fast to compute.

IQR
outlier if x < Q1 - 1.5 · IQR   or   x > Q3 + 1.5 · IQR

Distribution-free. Robust to skew. Based on quartiles.

Isolation Forest
s(x, n) = 2-E(h(x)) / c(n)

Implemented from scratch. Random recursive partitioning. Anomalies are isolated faster (shorter path lengths). Captures multivariate anomalies.

Airbnb Engineering Pipeline

  1. Price parsing: Convert "$1,234.00" string format to float
  2. Drop 26 irrelevant columns: URLs, free-text, metadata, scrape info
  3. Parse percentages: host_response_rate, host_acceptance_rate (remove '%')
  4. Boolean encoding: host_has_profile_pic, instant_bookable → 0/1
  5. Ordinal encoding: host_response_time (within an hour=4, few hours=3, day=2, days+=1)
  6. One-hot encoding: room_type, property_type (top 8), city
  7. Temporal: host_since → host_years (tenure as host)
  8. Imputation: 24 columns → median (robust to outliers)
  9. Outlier removal: Price 1st-99th percentile (186 rows removed)
  10. Near-constant removal: has_availability dropped

Result: 46 numeric features for modeling.

Non-Kernel Methods

Four algorithms implemented from scratch with NumPy

LR

Linear Regression (Ridge)

Closed-form solution: w = (XT X + λ I)−1 XT y. Lecture 7, Slide 10. L2 regularization prevents overfitting. λ=1.0.

LG

Logistic Regression

Gradient descent on binary cross-entropy loss. Sigmoid activation, L2 regularization. One-vs-rest for multi-class. lr=0.05, 300 iterations.

KN

K-Nearest Neighbors

Euclidean distance with efficient ||x-y||² = ||x||² + ||y||² - 2x'y expansion. k=5, majority vote (clf) / mean (reg). Batch processing for memory efficiency.

DT

Decision Tree

Gini impurity (classification) / MSE reduction (regression). Percentile-based threshold selection. max_depth=10, min_samples_split=5.

Kernel Methods

Four kernel algorithms exploiting the kernel trick

KR

Kernel Ridge Regression (Lecture 7, Slides 13-16)

α = (K + λ I)−1 y, predict via g(x) = Σi αi k(x, xi). The core algorithm from the course. Closed-form dual solution. Tested with Linear, Poly (d=3), and RBF kernels.

SV

Kernel SVM (Simplified SMO)

Sequential Minimal Optimization. Iteratively selects pairs of dual variables, optimizes subject to KKT conditions. C=1.0 regularization. One-vs-rest for multi-class.

KK

Kernel KNN

Uses kernel-induced distance: d2(x,z) = k(x,x) + k(z,z) - 2k(x,z). Avoids explicit feature mapping while computing distances in kernel space. k=5 neighbors.

KP

KPCA + Logistic Regression

Kernel PCA: eigendecomposition of centered kernel matrix. Projects data to top eigenvectors. Downstream Logistic Regression on projected features.

Why RBF Helped Airbnb But Not Others

The RBF kernel succeeded on Airbnb because superhost status depends on smooth, nonlinear interactions between host behavior (response rate, acceptance rate) and property metrics. These create a continuous, curved decision surface that RBF's infinite-dimensional feature space can approximate well.

Decision Trees outperformed kernel methods on IBM HR and Online Retail because these datasets have hierarchical, axis-aligned decision boundaries. Attrition depends on threshold-based rules (overtime > X AND satisfaction < Y), which trees capture naturally through recursive splits. The kernel trick adds computational overhead without improving the decision boundary geometry.

Error and Failure Analysis

Understanding why models fail is as important as celebrating when they succeed

Airbnb Price Failures

Worst predictions consistently occurred on luxury properties (>$1,000/night) and Albany listings (only 453 of 39,446 total). These are data quality artifacts: insufficient training examples in extreme ranges and underrepresented cities.

NYC 311 Classification Failures

Semantically overlapping categories (e.g., "Noise - Residential" vs "Noise - Street/Sidewalk") share geographic and temporal patterns. Classes with <10 test samples were consistently misclassified. These are label ambiguity issues.

IBM HR Attrition Failures

Misclassified employees had contradictory indicators: high satisfaction but high overtime and low compensation. These represent genuinely ambiguous boundary cases where the ground truth label may itself be questionable.

Online Retail Segment Failures

The Lost segment (6.2%) was the primary failure source. RFM segmentation creates hard boundaries that don't reflect the continuous nature of customer behavior transitions.

Theory vs. Reality: 5 Key Lessons

1. Missing data is the norm, not the exception▼

Airbnb had 24 columns with missing values. Textbook datasets have zero. This creates a false impression that missing data is minor.

2. Class imbalance fundamentally changes the problem▼

IBM HR's 5.2:1 ratio meant naive models hit 83.9% accuracy while being useless. SMOTE was essential. Iris has perfect balance.

3. Feature engineering dominates algorithm selection▼

Online Retail required complete transformation before any model could run. The 60/40 grading split reflects production reality.

4. The kernel trick is not universally beneficial▼

Kernels helped only Airbnb (+3.45%). They hurt Online Retail (-13%). Textbook XOR demos create a misleading impression.

5. Single-metric evaluation is insufficient▼

NYC 311 achieved 69.1% accuracy but only 44.4% macro-F1, masking total failure on minority classes.

Conclusion

Key findings from the investigation

Principal Findings
  1. Data quality dominated algorithm selection in determining model performance across all four datasets, validating the assignment's 60/40 grading emphasis.
  2. The kernel trick provided measurable benefit only on Airbnb (+3.45%), where the decision boundary involved smooth nonlinear host-property interactions. On three other datasets, non-kernel methods (especially Decision Trees) outperformed kernel methods.
  3. Decision Trees were the most robust method for tabular data, achieving best accuracy on IBM HR (82.7%), Online Retail (76.8%), and competitive performance on all datasets.
  4. Class imbalance and label sparsity caused consistent failures across all model families (IBM HR attrition minority, NYC 311 minority categories, Online Retail Lost segment).
  5. KRR Linear vs RBF on IBM HR (53.8% vs 78.8%) provided the strongest evidence of nonlinear manifold structure, demonstrating a 25-point accuracy improvement from the kernel trick alone.
