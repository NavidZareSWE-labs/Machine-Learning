HW3 — What Does the Assignment Want?

A plain-English breakdown of every requirement, grading weight, and deliverable.

Graduate ML — Spring 2026 Dr. Hashemi · TA: Ali Eskandarian 20–35 page report

Start HereThe Big Picture

This assignment is not a typical "implement an algorithm and report accuracy" homework. The very first paragraph of the PDF says it plainly:

Assignment's Own Words

"This assignment represents a paradigm shift from traditional algorithmic implementation. While you will build models from scratch, the primary challenge is not the code itself, but rather understanding when the dataset matters more than the algorithm."

In other words: the code is only 40% of your grade. The other 60% is about understanding your data — investigating its flaws, explaining why models fail, and connecting your findings to theory.

The Grading Split

25% — Data Quality Investigation (Section 2)
15% — Algorithmic Implementation (Section 3)
30% — Kernel Investigation (Section 4)
30% — Research Discussion (Section 5)

Notice that building the models is the smallest slice at 15%. The three analysis sections (25% + 30% + 30% = 85%) dominate your grade. The message is clear: think more, code less.

What You Must Deliver

Your final submission has two parts:

1
A 20–35 page Mini-Conference Paper (DOCX or PDF) — structured like an academic paper with 9 specific sections (listed below). This is your primary graded document.
2
A zipped code appendix — your fully commented, object-oriented Python scripts. The TA will read your code, but the paper is what earns the grade.

Key Insight

The assignment uses the word "manifold" to describe each dataset — it views them as fundamentally different geometric shapes in feature space. This is foreshadowing the kernel investigation: different data geometries favor different kernels.

Section 2 of the PDF — 25% of GradeData Quality Investigation

Before training a single model, you must investigate four dimensions of data quality for each dataset. The PDF requires you to "conduct and document a rigorous data quality investigation."

The Four Required Investigations

A
Missing Data Analysis
You must categorize missingness as MCAR, MAR, or MNAR — and prove it. Then defend your imputation math (why median? why mean? why drop?).
B
Outlier Analysis
Compare three specific methods: Z-score, IQR, and Isolation Forest. Show how they differ on your data. Which one flags the most? Why?
C
Feature Quality Analysis
Find redundant features (highly correlated pairs), data leakage (features that "cheat"), and near-constant features (no useful information).
D
Label Quality Analysis
Document potential annotation errors, ambiguous ground truths, and historical bias in the labels themselves.
What MCAR, MAR, MNAR actually mean
TypePlain EnglishHow to Detect
MCARMissingness is totally random — like coin flips deciding which cells are blankLittle's MCAR test; check if missingness correlates with any observed variable
MARMissingness depends on other observed columns (e.g., younger respondents leave income blank more often)Show that missingness in column A correlates with values in column B
MNARMissingness depends on the missing value itself (e.g., high earners refuse to report income)Cannot be proven from data alone — requires domain reasoning
Common Mistake

Many students skip this section or write a single paragraph. It is worth 25% of your entire grade — as much as the kernel investigation. Give it proportional effort: tables, figures, heatmaps, statistical tests.

Section 3 of the PDF — 15% of GradeAlgorithmic Implementation

You must implement eight models from scratch using only NumPy and SciPy. No scikit-learn. No machine learning libraries. Every core algorithm must be your own code.

The Eight Required Models

Non-Kernel Methods
Logistic RegressionClassification via sigmoid + gradient descent. Extend to multiclass with one-vs-rest.
Linear RegressionRidge regression: w = (XᵀX + λI)⁻¹Xᵀy. Closed-form solution.
K-Nearest NeighborsEuclidean distance, k neighbors, majority vote (classification) or mean (regression).

Constraint Reminder

You must run all eight models on all four datasets, on both classification and regression tasks (where applicable). That is up to 8 models × 4 datasets × 2 tasks = potentially 64 experiment runs.

Section 4 of the PDF — 30% of GradeKernel Investigation

This is the highest-weighted single section (tied with Discussion at 30%). Simply reporting numbers will get you zero credit here. The PDF is explicit about this:

Prohibited vs Expected — Directly from the PDF

Prohibited: "The RBF kernel got 92% accuracy, which is the best."

Expected: "The RBF kernel succeeded because the transformed feature space better captured the nonlinear, localized interactions created by the geographic coordinates and temporal variables in Dataset 2."

What "Mathematical Justification" Means

For each dataset, you need to explain why a specific kernel worked or failed by connecting three things:

1
Data Properties — What shape is the data? Continuous or categorical? Linear or curved boundaries? High or low dimensional?
2
Kernel Properties — RBF captures local similarity (nearby = similar). Polynomial captures global interactions (feature combinations). Linear assumes separability.
3
Why They Match or Mismatch — Connect 1 and 2. "The data has curved class boundaries (1) and RBF captures local curvature (2), so RBF outperforms Linear."
Example justification template you can adapt

"On the [Dataset Name] dataset, the [Kernel] kernel achieved [metric] = [value], outperforming [other kernel] by [margin]. This result is consistent with the data's [specific property — e.g., 'heavy-tailed price distribution', 'geographic coordinate features', 'binary-encoded categoricals']. The [Kernel] kernel's [mathematical property — e.g., 'localized Gaussian decay', 'polynomial feature interactions', 'linear inner product'] naturally captures [the specific pattern — e.g., 'diminishing returns of bedrooms on price', 'spatial clustering of complaint types']. In contrast, the [other kernel] failed because [specific mismatch — e.g., 'its global polynomial expansion amplified noisy categorical features']."

Section 5 of the PDF — 30% of GradeResearch-Level Discussion

This section requires five distinct discussion essays. Each tests a different analytical skill. Let's break them down one by one.

Discussion A: Cross-Dataset Comparison

Compare all four datasets directly. The PDF asks you to identify:

  • Which dataset was the hardest to clean
  • Which required the most aggressive feature engineering
  • Which benefited the most from the kernel trick
  • Which benefited the least from the kernel trick

Discussion B: Failure Analysis

For every dataset, find your model's 10 worst predictions. Then explain exactly why the model failed on those specific instances. Was it a model limitation (wrong inductive bias) or a data quality artifact (outlier, mislabeled, missing data)?

Discussion C: Bias and Fairness

Investigate sampling bias, temporal drift, and geographic bias in each dataset. Example: Airbnb data from Albany, NY cannot generalize to other cities. The IBM HR dataset may encode proxy discrimination.

Discussion D: Computational Analysis

Compare training time and memory usage. The PDF specifically mentions "the O(n²) and O(n³) complexities inherent in generating and inverting kernel matrices." You must discuss why kernel methods become impractical on large datasets.

Discussion E: Theory vs. Reality

The PDF poses a specific question you must answer with evidence from your experiments:

The Question

"Why do textbook datasets (like Iris or standard MNIST) consistently overestimate model performance and fail to prepare engineers for production machine learning?"

Your answer must use specific evidence from your four datasets — not generic statements.

Section 6 of the PDFReport Structure — The 9 Required Sections

Your submission must follow a specific 9-section structure. The PDF calls it a "Mini-Conference Paper." Here is each section with what belongs in it:

1
Introduction — Problem context, research objectives, what you are investigating and why.
2
Dataset Description & Topology — Describe all 4 datasets: size, features, targets, class distributions, unique challenges.
3
Data Cleaning & Feature Engineering — Your Section 2 work: missing data, outliers, feature quality, label quality, for each dataset.
4
Experimental Setup & Model Development — Describe the 8 algorithms, preprocessing pipeline, hyperparameters, train/test split, evaluation metrics.
5
Results — Tables and plots of all model performances. Classification: accuracy, F1, confusion matrices. Regression: R², RMSE.
6
Error & Failure Analysis — The 10 worst predictions per dataset per model. Why did they fail?
7
Cross-Dataset Comparison — Compare all 4 datasets. Which was hardest? Which benefited most from kernels?
8
Discussion — Bias & fairness, computational analysis, theory vs. reality (Discussions C, D, E).
9
Conclusion — Key findings, lessons learned, what you would do differently.
Length Requirement

20 to 35 pages, excluding the code appendix. The PDF says: "Do not submit a raw, unformatted Jupyter Notebook as your primary document."

StrategyRecommended Approach Order

Given the grading weights, here is a recommended priority order:

1
Data Quality First (25%) — Load each dataset. Run missing data analysis, outlier detection, feature quality checks. Generate all heatmaps and comparison plots. Write up findings.
2
Preprocessing — Build a per-dataset pipeline: impute, clip, scale, SMOTE. Verify clean data goes into models.
3
Implement Models (15%) — Start with the simplest (KNN, LinReg) to get a working pipeline, then add the complex ones (SVM, KPCA).
4
Kernel Investigation (30%) — Run all kernel types on all datasets. Analyze kernel matrices (eigenvalues, condition numbers). Write justifications.
5
Research Discussion (30%) — Cross-dataset comparison, failure analysis (10 worst), bias, computational analysis, theory vs. reality.
6
Write the Report — Compile everything into the 9-section paper. Embed all figures. Add captions and references.

How This Page WorksProgress Tracking

Every checkbox saves its state to your browser's localStorage. When you reload, your progress is restored automatically.

Why localStorage?

localStorage stores key-value pairs in your browser with no expiration. It was chosen over cookies because: (1) it has a simple setItem/getItem API, (2) it stores 5MB vs cookies' 4KB, and (3) data stays client-side — no server roundtrips. The tradeoff is that progress is per-browser and per-device.
